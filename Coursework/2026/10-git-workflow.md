# Практична 10. Командна робота з Git

**Мета.** Визначити безпечний процес внесення змін і перевірки перед злиттям.

**Запропонований процес для цього проєкту:**

1. Створити коротку гілку від актуальної `main`, наприклад `feature/save-slots`.
2. Змінювати пов'язані файли сцени, коду й `.meta` разом, перевіряючи `git status`.
3. Запустити цільові перевірки в Unity; додати результат і короткий опис у коміт.
4. Відкрити Pull Request із вимогою, кроками перевірки й скриншотом для візуальної зміни.
5. Переглянути конфлікти сцени й `.meta`, вирішити їх у Unity та повторно перевірити сцену.
6. Після схвалення злити в `main` і перевірити запуск.

**Ролі.** Силабус допускає індивідуальний проєкт. Для нього автор і перевіряльник — одна особа, але незалежний review був би корисним для сцен та бойових змін. Історію чужих review або злитих PR не наведено: підтверджень у цьому зрізі немає.

**Результат цієї практичної.** Описано процес і створено окрему гілку для навчального комплекту. Фактичний Pull Request/merge залежить від доступу до GitHub і не вважається виконаним без посилання на нього.
