# Практична 16. Автоматизовані перевірки

**Мета.** Описати наявні тести й їхню фактичну область покриття.

| Набір | Що перевіряє | Збережений результат |
|---|---|---|
| `BossDynamicVerification.cs` | Здоров'я 26, фази, атаки, хітбокси, смерть, перемога | `Evidence/boss-dynamic-results.txt`: 62 пройдено, 0 помилок |
| `BossArenaCollisionVerification.cs` | Рух героїні по підлозі, стрибок, ривок біля обох меж | `Evidence/boss-arena-collision-results.txt`: 10 пройдено, 0 помилок |
| `SelectedHoundVerification.cs` | Поведінка вибраних Ash Hound, шкода, анімація смерті | `Assets/Testing/AshHound/results.txt`: збережено рядки PASS |

**Код тестів.** `Assets/Editor/BossDynamicVerification.cs`, `Assets/Editor/BossArenaCollisionVerification.cs`, `Assets/Editor/Enemies/SelectedHoundVerification.cs`. Це редакторські перевірки зі збереженими результатами попереднього запуску, а не свіжий CI прогін для цього коміту.

**Межа покриття.** Перевірки не замінюють ручне оцінювання читабельності бою, музики й переходів на цільовій платформі. Для вимоги силабусу «3–5 тестів» достатньо виділити окремі сценарії, наприклад: перехід фази, активне вікно кігтя, завершення смерті, ліву/праву межу арени та стрибок. Вони є всередині двох наборів, але не оформлені як окремий CI pipeline.
