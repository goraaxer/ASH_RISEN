# Практична 19. Зміна вимоги та аналіз впливу

**Мета.** Показати, як керувати зміною після реалізації першої версії.

**Зміна CR-1.** Початкова модель збереження — один локальний JSON файл. Нова навчальна вимога — кілька слотів, які можна створювати, читати, редагувати, видаляти й шукати/фільтрувати. Вона випливає з мінімальних вимог силабусу до навчального програмного продукту; зміна ще **не реалізована**.

**Вплив.** `GameSaveSystem.SavePath` зараз повертає один шлях `ashrisen-reset-save.json`. Для слотів потрібен окремий ідентифікатор, список метаданих, перевірка назви, міграція старого `GameSaveData.version = 2`, оновлення меню та обробка частково записаних файлів. Тести мають охопити відсутній слот, некоректний JSON, дубльовану назву, відмову файлової системи й видалення активного слота.

**Пропоновані критерії приймання.** Старе збереження відкривається або імпортується без втрати прогресу; створення не перезаписує інший слот; видалення потребує явної дії; пошук не змінює дані; помилка запису показується гравцеві.

**Рішення для поточного зрізу.** Залишити наявний формат незмінним, записати CR-1 в backlog (практична 17), реалізувати в окремій ітерації та повторно пройти M5–M6. Не позначати вимогу як виконану до коду й перевірок.
